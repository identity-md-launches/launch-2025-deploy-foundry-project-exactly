# Launch adaptation

This remains a contracts-only launch on Robinhood Chain (4663), in the committed
order: DrandBeacon, IdentityMachine, MachineViews, EthMinter. Constructor
signatures, argument values, `launch.json`, compiler settings, and dependencies
are unchanged. `$owner` remains the developer payout address
`0x7bfb800906d744b8f43286ca97ef7b32e61edb39`; the factory receives no application
ownership or administrative role. No transactions were broadcast.

## Changes and reproduced findings

1. **External pool checks prevented the factory rehearsal**
   (`5c9d4fcbdd9cd2c71c973cc10b73ec0432a244abb5bb71088b5c08867fa1a81b`).
   The supplied proof reproduced `BadPool()` when the manifest's PoolManager and
   Quoter had no code. In `src/EthMinter.sol`, their code-presence and
   quoter-to-manager checks now run before every quote or swap, including referral
   purchases. Constructor checks for fee, spacing, and the previously deployed
   machine remain. There is no initializer, mutable configuration, or validation
   cache. Valid checkout pricing, slippage limits, callbacks, refunds, and
   beneficiaries retain their existing behavior.

   `test/LaunchDeployment.t.sol` reads the existing manifest, resolves its
   backward references and the supplied owner, and deploys all four applications
   through a single zero-value CREATE2 factory call without external dependencies.
   It checks predicted addresses, immutable wiring, payout destination, inventory
   authority, runtime size, forbidden opcodes, and clean rejection of checkout
   before dependencies exist. `test/security/Checkout.t.sol` moves the old
   constructor-only dependency assertions to first use and covers missing code,
   mismatched managers, reverting validation, retry, later dependency availability,
   validation after a successful quote, and both purchase entry points. The
   existing manifest's prose about constructor pool validation describes the old
   timing; its deployment arguments were deliberately preserved.

2. **Missing art fixture broke the committed test suite**
   (`98828aa3a148158586f0bf2de966ae4fc1f8f995b9cdf3cd0d1e7ba41ff5c7d6`).
   `DeployTest.test_artTemplatesMatchShapes` reproduced the missing-file failure.
   `art/out/templates.json` is now included, generated by the unchanged
   `art/parts.mjs` in a temporary output tree. That generation also reproduced the
   existing catalog and frontend art byte for byte. `.gitignore` now permits this
   fixture while keeping other generated art ignored. The original Solidity test
   checks every template cell and socket; it is neither skipped nor weakened.
   A fresh offline checkout needs no Node generation step to run it.

3. **Seat 65535 overflowed its stored seat-plus-one value**
   (`7a93697bfa5def840b66a2a054d5aa279565988843894685955c1952d7c18489`).
   A valid single-leaf proof reproduced panic `0x11`. As required for reproduced
   audit findings, `src/IdentityMachine.sol` now widens before addition and stores
   `seatPlus1` as `uint24`. `src/MachineViews.sol` returns the same wider type so
   seat 65535 is represented as 65536 rather than truncated. The two affected
   frontend ABIs (`app/src/abi/IdentityMachine.json` and
   `app/src/abi/MachineViews.json`) and the typed readers in
   `test/security/Lifecycle.t.sol` and `test/security/Views.t.sol` match that type.
   The `uint16` claim argument, Merkle leaf encoding, root, and replay protection
   are unchanged. `test/AgentCoreSeats.t.sol` checks seat 0, seat 65535, fuzzed
   uint16 seats, unauthorized claims, duplicate claims, inventory ownership, and
   lossless view results.

   The committed snapshot has exactly 2,000 distinct seats, 0 through 1999, so
   this was not reachable with the launch root. The fix supports the entire
   accepted input type. It changes the `Part` storage packing (the unchanged
   `uint112 plug` occupies a second slot) and the seat output ABI types; this is a
   fresh deployment, with no upgrade or storage migration. Other part fields and
   economic limits are unchanged.

4. **External IMD blocklist authority**
   (`d8f860581bd431bf56d1bc46fe146d28534f557d184051f2184e7ca4297da0e0`).
   The existing `ForkTest.test_imdOwnerBlocklistCanFreezeAHolder` reproduced
   blocked outgoing and incoming transfers on a fork at block 90,378,976.
   This is an external dependency trust assumption, not an application capability
   that this project can remove. IMD's owner can prevent transfers involving a
   blocked address. Blocking the machine can stop purchases and withdrawals;
   blocking the burn recipient can stop purchases; blocking a player or the
   developer can prevent their payouts. Transaction rollback preserves accounting,
   but recovery depends on the token owner allowing transfers again. The token
   address and all requested beneficiaries remain unchanged.

## Verification

Validation uses the project's unchanged default Foundry configuration and
`FOUNDRY_FUZZ_SEED=0x58343bfb2f5a303aa2e7b4ccc15fcc1a25fa19801efc18ca0f6915718497dac6`.
All four reported observations reproduced; the external token authority remains
documented because it is outside these contracts. The three local defects above
were reproduced before their fixes.

- `forge build` passes with the original settings. Its existing unused `deployer`
  parameter warning in `script/Deploy.s.sol` remains unrelated to these changes.
- `forge test` with the seed above passes: **231 passed, 0 failed, 3 skipped**
  across 29 suites. The five invariants pass together over 128 runs and 16,384
  handler calls with zero reverts. The three skips are the existing fork-only
  tests on the offline chain; two were also run separately as listed below.
  The live drand end-to-end fork test (`ForkTest.test_onRobinhood`) was not run.
- The 36 focused deployment, art, seat, and checkout regression tests pass
  (the checkout suite was rerun after correcting its absent-code test helper).
- Both updated frontend ABI files exactly match their compiled ABIs. Constructor
  signatures remain static and nonpayable, with at most six arguments; all four
  application bytecodes have no unresolved library links.
- `ForkTest.test_imdOwnerBlocklistCanFreezeAHolder` passes on a read-only fork at
  block 90,378,976, using the existing test without enabling FFI.
- `EthMinterForkTest.test_liveExactOutputPool` passes on the same block: the
  quoter agrees with the real swap, the payer receives the pending parts, unused
  ETH is refunded, and the helper retains no payment funds or token allowance.
